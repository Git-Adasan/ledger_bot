# Личный бот учёта: заказы, клиенты, долги, доходы и расходы

Только для владельца. Python 3.11+, aiogram 3, SQLAlchemy 2, SQLite.

## Запуск
1. `pip install -r requirements.txt`
2. Скопируйте `.env.example` в `.env`, укажите `BOT_TOKEN` (от @BotFather) и `OWNER_IDS` (ваш Telegram ID, узнать у @userinfobot).
3. `python -m ledger_bot`
4. Тесты: `python -m pytest -q`

Остальные пользователи бота полностью игнорируются.

## Как устроено
- Деньги хранятся целыми тиынами, количество — тысячными долями; округление «половина вверх».
- Услуги, категории, цены, единицы и варианты (например, тип печати у альбома) меняются в боте: «Каталог услуг». Код под новую услугу не нужен.
- В заказе хранится снимок: название, количество, единица, цена, сумма. Изменение каталога старые заказы не трогает.
- Долг и переплата считаются из записей (заказы, платежи, распределения платежей, списания). Итоги не перезаписываются. Отмена заказа освобождает распределение платежа (запись остаётся с `released_at`), деньги становятся переплатой клиента.
- Переплата автоматически закрывает новые и открытые долги. Возврат переплаты — отдельная запись.
- Заказ «без клиента» считается оплаченным сразу (личная финансовая запись). При его отмене создаётся запись возврата.
- Повторные нажатия и дубли: у заказов, платежей, возвратов, списаний и операций есть ключ идемпотентности; каждая операция — одна транзакция с откатом при ошибке.
- Статистика разделяет: стоимость заказов, полученные деньги, другие доходы, расходы, долг клиентов. Итог называется «движение денег», не «чистая прибыль».
- Резервные копии: автокопия раз в 24 часа и при запуске (`data/backups`, хранится 30), ручная копия файлом в Telegram, восстановление из присланного файла с проверкой и страховочной копией текущей базы.
- Автокопия в Telegram: после изменений (заказ, оплата, правка каталога и т. д.) через ~10 секунд тишины бот присылает вам файл копии без звука. В подписи — число клиентов, заказов и платежей. На бесплатном хостинге, где файлы стираются, это единственная защита данных.
- Экспорт: ZIP с CSV-файлами (UTF-8, открываются в Excel).

## Размещение на Render
1. Распакуйте архив и загрузите **содержимое папки** `ledger_bot_project` в репозиторий GitHub (сам zip загружать не нужно; файл `.env` не загружайте, он в `.gitignore`).
2. На Render: New → Web Service → подключите репозиторий, Language/Runtime: Python 3.
3. Build Command: `pip install -r requirements.txt`. Start Command: `python -m ledger_bot`.
4. Environment: `BOT_TOKEN`, `OWNER_IDS`, при необходимости `PYTHON_VERSION` (нужен Python 3.11 или новее) и `TIMEZONE`.
5. Адрес `/health` подключите к UptimeRobot (см. ниже).

## Мониторинг (UptimeRobot)
Если задан `PORT` (его выдаёт хостинг) или `HEALTH_PORT`, бот отвечает «ok» на `/health` и на `/`: 503, если не открывается база. Этот адрес указывают в UptimeRobot как HTTP-монитор. Без порта адрес не запускается.

## Ограничения
- Если хостинг стёр файл базы, бот при запуске напишет об этом. До начала работы пришлите ему последний файл копии (Настройки → Восстановить из копии). Потерять можно только то, что было после последней присланной копии.
- Состояние диалога хранится в памяти: после перезапуска бота незаконченный ввод сбрасывается (сохранённые данные не теряются).
- Начальные цены альбома по гистологии (35 и 55 ₸ за лист) — предположение; поменяйте в «Каталог услуг → Варианты».
